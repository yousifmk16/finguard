2) What Will Be Implemented
- Tool selection: Locust (Python, fits backend stack) or k6 (better stats output) — decide before TST-07 sprint kickoff.
- SLA target: end-to-end latency < 60s, measured as event ingest timestamp -> anomaly visible in UI / alert table.
- Three load profiles:
    a) Baseline: steady N events/sec for 10 min — validates p95 latency under nominal load.
    b) Peak: ramp to 5x baseline over 2 min, hold 5 min — validates SLA under burst.
    c) Soak: baseline x 60 min — checks for memory creep, queue backpressure, stream-broker lag.
- Metrics captured per run:
    - p50 / p95 / p99 ingest -> anomaly_persisted latency
    - p95 anomaly_persisted -> alert_emitted latency
    - p95 alert_emitted -> UI visible latency (via API poll, not browser)
    - Stream broker consumer lag, DB write latency, detection service CPU/mem
- Pass/fail gate: p95 end-to-end < 60s on baseline AND peak; soak shows no monotonic degradation.
