2) What Was Implemented
- TypeScript types `AnomalyRecord`, `AnomalyListResponse`, `AnomalyListQuery` mirror
  the backend `AnomalyResponse` / `AnomalyListResponse` schemas exactly so the client
  parses the API-01 payload without runtime massaging.
- `listAnomalies(query, token)` builds a URLSearchParams object covering every
  documented filter (account_id, service, region, severity, status, from_bucket,
  to_bucket) plus pagination (page, page_size). UI-05 will wire filter values into
  this call without changing the page shell.
- `useAnomaliesList(query)` is a self-contained data hook: it owns loading/error
  state, aborts the in-flight request when the query changes or the component
  unmounts, re-runs only when the serialized query, token, or reload key changes,
  and exposes a `reload()` function for the manual refresh button.
- 401 from the API triggers `signOut()` so the AuthProvider clears the session and
  ProtectedRoute redirects to `/login?reason=expired`. 403 surfaces a dedicated
  "no permission" message; network failures and other errors degrade gracefully
  with a retry button in a `state-banner--error` strip.
- Pagination state lives in the URL via `useSearchParams` (`?page=2&page_size=25`),
  so back/forward, refresh, and shared links all return to the same view. The
  default page size is 25 and is clamped to the API's documented 1..200 range.
- The table renders the columns from the UX-01 wireframe (ID, Account, Service,
  Region, Score, Severity, Status, Detected) plus a "View detail" link that routes
  to `/anomalies/:anomalyId` (UI-04). Anomaly IDs are truncated for density and
  expose the full UUID via the link's `title` attribute.
- Severity and status are rendered with reusable badge components keyed by lower-
  cased value so future statuses inherit base styling automatically. Badge
  palettes follow the FinGuard severity convention: high=red, medium=amber,
  low=blue, none/suppressed=muted; resolved=green, acknowledged=amber, open=red.
- Explicit empty / loading / error states (per UX-01 "Global UX Rules"):
  - Loading (first fetch): "Loading anomalies..." placeholder row, table marked
    `aria-busy`.
  - Empty: "No anomalies match the current view." placeholder row.
  - Error: dismiss-free banner with the failure message and a "Try again" button
    that triggers `reload()`.
  - Background refresh: existing rows stay on screen and the Refresh button
    label switches to "Refreshing...".
- Pagination summary reads "Showing X-Y of Z" when results exist and "No results"
  when empty, matching list-view conventions and a11y-friendly to screen readers.
