2) What Was Implemented
- `useAnomaly(anomalyId)` calls `getAnomaly()` (already exported from
  `anomalies-api.ts` for UI-03), aborts on unmount/id change, and surfaces
  loading, error, and `notFound` flags as separate state. 401 triggers
  `signOut()`; 403 surfaces a permission message; 404 flips a dedicated
  `notFound` flag so the page can render the proper "could not be found"
  state per UX-02.
- The page renders the UX-02 wireframe layout with real data:
  - Breadcrumbs (`Dashboard / Anomalies / <id>`) and a "Back to list" link.
  - Header card showing the anomaly id (monospace, breakable) plus
    severity and status badges; a `<dl>` summary grid with Account,
    Service, Region, Bucket, and Detected timestamps.
  - "Score Summary" card showing the final score prominently, the
    score breakdown rendered from `anomaly.score_breakdown` as a
    label/value grid (numeric values are toFixed-3 for sub-component
    scores), and an explanation paragraph if `score_breakdown.explanation`
    is present.
- "Lifecycle Actions" and "Related Alerts" are intentionally rendered as
  placeholder cards labeled with their owning task (UI-08, UI-07). UI-08
  will replace the placeholder with the real action buttons hitting
  `PATCH /api/v1/anomalies/{id}/status`; UI-07 will surface anomaly-linked
  alerts once the alerts API exposes an `anomaly_id` filter (today's API-04
  endpoint only filters by account/service/region).
- Explicit loading / 404 / error states (per UX-02 "States to support"):
  - Loading: subtle "Loading anomaly..." status banner.
  - 404: error banner with "Anomaly {id} could not be found." and a
    direct "Back to list" link.
  - Other errors: error banner with the server-provided detail and a
    "Try again" button that calls `reload()`.
- Generic helpers in the file (`prettifyKey`, `renderBreakdownValue`,
  `pluckExplanation`) defensively format unknown payload shapes from
  `score_breakdown: dict[str, Any]` so the page does not break if the
  detection engine adds new keys later.
