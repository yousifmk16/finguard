2) What Was Implemented
- Vite + React 18 + TypeScript + React Router 6 scaffold replacing the Sprint 0 placeholder
  scripts. `npm run dev` now serves the real app on port 3000 (Docker-compatible host
  binding); `npm run build`, `npm run typecheck`, and `npm run lint` are wired.
- App shell mirrors the UX-01 dashboard wireframe: left sidebar with primary nav
  (Dashboard, Anomalies, Alerts, Policies [Admin], Users [Admin], Settings), a brand
  block, a topbar with user role/email and sign-out, and a scrollable content region
  rendered through React Router's `<Outlet />`.
- Routing: `/login` (public), `/forbidden`, `/` -> `/dashboard`, plus `/dashboard`,
  `/anomalies`, `/anomalies/:anomalyId`, `/alerts`, `/settings` behind
  `ProtectedRoute`, and `/policies` + `/users` additionally behind `AdminRoute`. A
  catch-all `*` route serves the 404 page.
- Auth context (`AuthProvider`) holds `{ token, user: { userId, email, role } }` in
  React state and persists to `localStorage` so a refresh keeps the user logged in.
  `useAuth` exposes `session`, `isAuthenticated`, `setSession`, and `signOut`.
- Route guards: `ProtectedRoute` redirects unauthenticated users to `/login` and
  remembers the requested path in `location.state.from`, so post-login navigation
  returns the user to where they were heading. `AdminRoute` redirects non-admin
  users to `/forbidden`.
- Role-aware sidebar: items flagged `adminOnly` are filtered out for analyst sessions,
  satisfying the UX-04 expectation that analysts never see admin destinations
  (UI-09 will extend this to in-page action visibility).
- `LoginPage` is intentionally a shell stub with two buttons that synthesize an
  analyst/admin session for end-to-end shell testing. UI-02 replaces this with the
  real credential form against `POST /api/v1/auth/login` (SEC-01).
- Vite dev proxy forwards `/api/*` to `VITE_API_PROXY_TARGET`
  (default `http://localhost:8000`), keeping the frontend single-origin in dev.
- Global CSS provides shell layout, focus ring, mobile collapse for the sidebar,
  and theming tokens; per-feature pages will layer on top in UI-02..UI-09.
